# FenPei 文件分发工作台

面向局域网多台电脑的文件夹分发与上传监控应用。当前维护入口是 `go-dist/` 中的 Go 应用，浏览器前端随服务端编译进二进制。

## 启动

首次构建或修改代码后，需要 Go 1.22 或更高版本：

```bash
cd /home/jyzn/桌面/fenpei/go-dist
bash build.sh
```

启动服务端（无需指定硬盘目录）：

```bash
cd /home/jyzn/桌面/fenpei/go-dist
./bin/fenpei-server --host 0.0.0.0 --port 8000
```

保持终端打开；按 `Ctrl+C` 停止服务并保存状态。以后启动时使用同一工作目录，以恢复已有任务池。

- 服务端这台电脑访问：[http://127.0.0.1:8000](http://127.0.0.1:8000)。
- 同一局域网的其他电脑访问：`http://服务端局域网IP:8000`。当前示例为 `http://10.75.78.226:8000`，更换网络后 IP 可能变化，可运行 `ip -brief address` 查看实际联网网卡地址。
- 浏览器代理应绕过本机和局域网地址。不要使用 Meta 虚拟网卡地址 `198.18.0.1` 作为应用访问地址。

服务端可以空池启动。插入并挂载移动硬盘后，登录管理员账号，在「数据池管理」的「加入硬盘数据」，点击「选择文件夹」，浏览并选中源电脑上的挂载目录，也可输入绝对路径，例如 `/media/jyzn/数据盘/采集数据`，点击「扫描目录」，再点击「加入数据池」。浏览器访问的电脑无需直接读取硬盘，扫描发生在源电脑。

该目录下包含文件的一级子文件夹各是一项任务；隐藏一级目录、空目录、符号链接以及目录根部直接放置的文件不导入。文件从原目录只读提供，不先复制到服务端。多块硬盘可以依次添加，两块硬盘上的同名文件夹按来源 ID 隔离，客户端分别存放在 `received/<来源ID>/<原始文件夹名>/`。平台匹配从原始文件夹名称末尾提取八位日期编号（例如 `20261010`），在当前 JZ 平台账号的任务中查找相同末尾编号，不要求前面的名称一致。没有编号、没有匹配任务或多个不同任务 ID 匹配时均报错，不自动选择。新建任务先开始采集、再结束采集，之后获取路径上传；进行中/采集中任务先结束采集，已完成任务直接进入后续步骤。

同一目录重复加入或重新扫描只添加新文件夹，保留已有任务、完成记录及原文件清单。已有文件夹内部新增或修改的文件不会自动更新，因此加入后应保持该任务数据不变。仍有任务的父子目录重叠来源会拒绝导入，以免重复分发同一数据。没有任务的残留来源不阻止加入；启动时自动清理空来源。同一路径检测到设备标识变化且仍有旧任务时，拒绝直接复用，需先移除旧任务。扫描会读取文件并计算 SHA-256，因此扫描大目录所需时间会增加。

硬盘不可读取时不分配它的任务；正在下载的文件可能失败。重新挂载到原路径后，可在「加入硬盘数据」中再次输入原路径并扫描，加入新增任务。当前以路径和文件系统设备号辅助判断是否可读，没有使用硬盘序列号或 UUID，所以不能自动识别“另一块硬盘挂在相同路径”的情况。

任务池为空、全部任务暂不可领取或分发暂停时，新版客户端持续等待，通过长轮询进入服务端等待队列；来源添加、任务恢复或分发恢复后服务端按队列顺序分配。一轮领取请求最多保留 45 秒，到期后立即重新入队；网络故障时等待 3 秒重新连接。空闲客户端约每 9 秒独立上报心跳，有任务时仍每 3 秒上报进度。旧版客户端不具备该等待逻辑及原始名称匹配字段，请更新客户端二进制；旧版客户端的领取请求会被拒绝并提示重新下载。

状态文件 `distribute_state.json` 位于服务进程的工作目录。重启时保持相同工作目录会恢复全部来源和任务，即使硬盘暂未连接。旧单目录状态自动补全来源记录；建议升级前备份已有状态文件。无效状态文件会拒绝启动，避免覆盖原数据。仍可用 `--source /实际路径` 在启动时向池子追加一个目录。

目标电脑可从服务端下载 Linux amd64 客户端（将示例 IP 换成实际服务端 IP）：

```bash
wget http://10.75.78.226:8000/client -O fenpei-client
chmod +x ./fenpei-client
./fenpei-client
```

运行后自动寻找同一局域网／子网内的服务端并连接，同时打开本机页面 `http://127.0.0.1:18080`。发现服务端不会自动领取任务，点击「开始工作」才开始下载、压缩和上传。

客户端页面独立于服务端控制台，仅展示开始／继续工作、暂停、当前任务的下载／压缩／上传进度和运行日志。没有数据池管理或全局分发控制入口。日志显示最近 500 条，完整运行日志保存在 `received/logs/client_YYYYMMDD.log`。

「暂停」立即停止本机工作进程，下载、压缩、上传及重试等待一起暂停；控制进程继续维护心跳和任务归属，不影响其他客户端。点击「继续工作」恢复同一个工作进程及其步骤缓存。暂停无法撤回远端已经收到的请求或操作；已发出的少量网络缓冲数据可能继续到达。长时间暂停后，远端超时的请求可能按原有规则重试，MinIO 未完成的单次 PUT 会重新上传。

自动发现使用子网 UDP 广播，默认与服务端 HTTP 使用相同端口号 8000。服务端同时监听 TCP 和 UDP。未发现时持续重试，连接断开后自动重连原服务端，避免处理到一半换到另一台服务器。跨子网、无线客户端隔离或防火墙阻断 UDP 广播时，可指定服务端：

```bash
./fenpei-client --server http://服务端IP:8000
```

服务端使用其他端口时，用 `--discovery-port 端口号` 指定发现端口。`--dest` 可设置保存目录，`--no-browser` 只显示页面地址，`--ui-port` 可修改本机页面端口（操作员远程入口默认连接本机 18080）。本机页面只监听回环地址，并校验 Host 和请求来源。

默认下载后自动上传，需要目标环境能够访问上传平台和对象存储。使用 `--upload=false` 可仅下载。需要兼容原命令行直接工作模式时：

```bash
./fenpei-client --headless --server http://服务端IP:8000 --dest ./received --upload=false
```

当前下载包仍是 Linux amd64 可执行程序；下载后需赋予执行权限并运行，浏览器下载本身不会执行程序。

等待队列只记录运行期的有效领取请求，不保存到磁盘。客户端断线、请求取消或长轮询到期会离队，重新连接时排到队尾。同一客户端身份同时等待的重复请求会被拒绝。服务端每 5 秒集中检查来源重新可读、任务超时等变化，避免要求客户端频繁查询。心跳用于在线状态，不是领取请求。

## 上传重试与错峰

默认首次尝试之外最多重试 5 次，即每个文件夹最多执行 6 轮上传流程。重试会从未确认成功的步骤继续，每轮可能调用多个平台接口，该上限不是 HTTP 请求总数。所有失败阶段都使用同一有限预算，不再每 3 秒无限重试。

每个文件夹首次上传前随机等待 1～15 秒。失败后的等待按指数增长，并在区间内独立随机选择：第 1 次 15～30 秒、第 2 次 30～60 秒、第 3 次 60～120 秒、第 4 次 120～240 秒、第 5 次 240～480 秒；更多重试的等待上限为 600 秒。随机数不使用相同的启动种子，减少多台电脑同时重试。

可通过客户端参数设置 1～20 次重试，例如：

```bash
./fenpei-client --server http://192.168.1.10:8000 --dest /path/to/received --upload --upload-retries 3
```

达到上限后记录 `retry_exhausted`，数据池状态显示“上传异常”，悬停可查看回报原因。保留本地文件夹及已生成的 ZIP，停止该任务的自动上传，客户端继续领取其他任务。当前页面没有“重新上传”入口，重新加入同一来源也不会重新执行已下载完成任务的上传。

等待期间最多每 30 秒检查服务端的成功 / 跳过标记。当前任务处理中缓存已经确认成功的步骤：登录、任务匹配、平台心跳、开始/结束采集、任务信息、存储配置与 ZIP 上传。后续步骤失败不重做前面的成功步骤。ZIP 成功但平台完成通知没有回复时，只重试同一任务的完成通知；HTTP 401/403 时重新登录，MinIO 403 时重新获取存储凭据。多个客户端仍可同时上传，未加入串行上传限制。

缓存只在当前客户端处理该任务期间存在，进程重启后不会恢复上传步骤。响应丢失的步骤仍可能重复请求，尤其是开始/结束采集与上传通知；是否可完全去重依赖平台的幂等约定，尚未通过真实平台验证。随机退避与次数上限用于约束这些必要重试。

## 本系统账号与界面分流

浏览器访问根地址会先进入 `/login`。管理员登录后进入 `/server`；操作员登录后进入独立的 `/workspace`。两种界面独立维护，操作员无法访问服务端管理接口。操作员的 `/workspace` 使用独立客户端界面，连接访问电脑上已启动的客户端控制进程；未运行时显示启动提示。下载的客户端也会自动打开本机工作页面，直接控制这台电脑的任务。

账号来源是服务端环境变量，与上传平台账号无关：

- `FENPEI_ADMIN_USER`：管理员账号，默认 `admin`。
- `FENPEI_ADMIN_PASSWORD`：管理员密码，默认 `root`，重启后保持不变；设置该环境变量可覆盖默认密码。
- `FENPEI_OPERATOR_USER` / `FENPEI_OPERATOR_PASSWORD`：可选操作员账号和密码，需同时设置，且账号不得与管理员相同。

例如使用交互输入设置密码后启动（密码不写入命令历史）：

```bash
export FENPEI_ADMIN_USER=admin
read -rsp '管理员密码: ' FENPEI_ADMIN_PASSWORD
export FENPEI_ADMIN_PASSWORD
./bin/fenpei-server --host 0.0.0.0 --port 8000
```

当前支持一名管理员和一名可选操作员，暂不提供页面内账号管理。登录会话有效期为 12 小时，退出或服务重启后失效。管理员能暂停新任务分发；已领取任务继续处理，恢复后按队列顺序分配。运行记录展示本次运行最近 200 条记录。

## 页面功能

管理员专用控制台位于 `/server`，按导航切换运行总览、数据池管理、客户端监控和运行记录：

- 数据池：文件夹、来源目录、文件数、大小和状态；支持搜索、分页和删除。删除仅移除池中任务记录，保留硬盘原文件；已被领取或仍在处理的任务暂不能删除。删除后重新扫描并加入原目录，可再次把该文件夹加入池子。删除来源的最后一个任务后会移除空来源，可加入其上级目录。
- 等待队列：当前正在服务端排队领取任务的客户端数量。
- 工作进度：每台在线客户端的当前任务及下载、压缩、上传阶段进度；等待平台确认或退避重试时显示阶段，不虚构百分比。
- 连接客户端：按最近 15 秒内的心跳或进度报告判断在线，显示电脑名称、IP 和工作状态。

“加入硬盘数据”入口默认展开，可直接选择源电脑上的文件夹，扫描后可把新的一级子文件夹加入池子。同一路径可再次扫描，加入新增任务。

状态每两秒从本服务刷新；隐藏页面暂停定时请求，返回时立即更新。页面刷新不请求上传平台。连接失败会提示当前显示上次成功获取的数据。数据池中的“已下载”不等于“已上传”。工作进度来自客户端报告，并非操作系统进程监控。

## 维护结构

```text
go-dist/
  cmd/                         服务端与客户端启动入口
  internal/server/server.go    分发、状态持久化与 HTTP 接口
  internal/server/pool.go      来源扫描、增量入池、可用性与文件映射
  internal/server/queue.go     客户端 FIFO 等待队列、长轮询与唤醒
  internal/server/web.go       静态资源嵌入与路由
  internal/server/auth.go      本系统账号、会话及管理员权限校验
  internal/server/web/
    login.html                 统一登录入口
    auth.css                   登录页样式
    server/index.html          管理员专用页面结构
    server/style.css           服务端视觉样式和响应式布局
    js/api.js           HTTP 请求与接口封装
    server/view.js          数据格式化与页面渲染
    server/app.js           单页刷新、搜索分页与来源加入流程
  internal/client/client.go    下载与客户端通信、真实进度回调
  internal/client/agent.go     本机页面、工作进程启停、独立心跳与日志
  internal/workspace/web/      客户端 HTML / CSS / JS（独立于服务端 UI）
  internal/discovery/          局域网广播发现与服务标识校验
  internal/uploader/           压缩、平台上传、步骤缓存与有限重试
  internal/protocol/           通信结构与状态约定
```

前端使用原生 ES 模块，无需额外 Node 构建步骤或在线 CDN。修改页面后重新编译服务端并重启；直接启动旧二进制不会应用源码中的前端变化。服务端接口变更同时更新 `api.js` 与 `view.js`，业务状态约定集中维护在 `internal/protocol/`。

根目录的 Python 文件是已有脚本入口。本次浏览器应用接入 Go 服务端。

## 后续应用化方向

当前已支持动态多来源任务池。长期维护可逐步增加硬盘身份识别、已有任务显式更新、可持久化的应用配置、服务安装、多账号管理与设备鉴权、多批次任务、日志持久化及版本发布流程。管理页面及管理接口已要求管理员登录；现有客户端协议与文件下载接口仍沿用原有局域网通信方式，尚未接入设备鉴权。

### 安装版客户端（Linux x64 / amd64）

运行 `bash go-dist/build-deb.sh` 生成 `go-dist/dist/fenpei-client_1.2.2-1_amd64.deb`。将安装包复制到目标电脑，运行 `sudo apt install ./fenpei-client_1.2.2-1_amd64.deb`，然后从应用菜单打开“FenPei 分配客户端”，或运行 `fenpei-client`。安装不会自动开始工作。

安装版下载数据及日志位于 `${XDG_DATA_HOME:-$HOME/.local/share}/fenpei-client/`，无需以 root 运行客户端。再次启动会打开现有客户端页面；卸载保留用户数据。命令行参数可透传，例如 `fenpei-client --server http://192.168.1.10:8000`。

### 统一安装版（1.2.3 起）

客户端和服务端使用同一个 amd64 Deb 包 `go-dist/dist/fenpei_1.2.3-1_amd64.deb`、同一个应用“FenPei 文件分发”和同一个命令 `fenpei`。运行 `bash go-dist/build-deb.sh` 可重新生成安装包。安装命令：`sudo apt install ./fenpei_1.2.3-1_amd64.deb`；此包替换先前的 `fenpei-client` 安装包。

两台电脑分别打开应用，在本机 `http://127.0.0.1:18080/login` 登录：服务端使用 `admin / root`，客户端使用 `pc01 / root`。管理员登录后本机才启动 TCP/UDP 8000 服务；客户端登录后才启动自动发现与保活，点击开始工作后领取任务。两个页面按账号分流，客户端不能访问管理接口。退出登录不关闭已经启动的后台角色；关闭程序才关闭后台服务。新版本数据、任务池和日志保存在 `${XDG_DATA_HOME:-$HOME/.local/share}/fenpei/`，旧客户端用户数据仍保留在原目录。

测试前退出旧程序，避免旧服务端占用 8000 或旧客户端占用 18080。上述统一安装版说明替代此前仅客户端 Deb 的安装说明。平台上传规则仍为末尾八位日期编号唯一匹配，新任务先开始再结束采集，然后上传。

## 数据池可靠性修复

服务端和客户端需一起更新：新版客户端使用任务池协议 2，完成回报携带每次领取的随机凭证；旧客户端领取任务会收到升级提示。重复完成回报只计数一次，失效领取的回报不能覆盖新归属。

新扫描的文件包含 SHA-256，客户端在复用和下载结束时校验内容。未经校验的旧断点从头下载；旧状态没有校验值的文件也从头下载，删除后重新加入可生成校验值。当前清单以外的客户端旧文件移到接收目录下 `.stale-task-*` 备份目录，避免混入 ZIP；压缩缓存按领取凭证隔离，同一轮上传重试仍可复用。

状态通过临时文件写入、同步后原子替换。保存失败时管理页面持续显示警告，服务端每 5 秒重试；恢复后警告自动清除。操作响应仍表示内存状态已更新，出现保存警告时，最近操作尚未可靠落盘。

## GitHub 发布与自动检查更新（v1.3.0）

两个工作台启动后自动检查稳定版，工作台打开时每分钟读取本机缓存；外部检查成功缓存一小时、失败五分钟后重试。点击“检查更新”可提前刷新，至少间隔 30 秒。发现新版后显示下载安装包和更新说明链接。检查失败不影响任务，页面会显示原因。本版尚不自动安装、重启或回退，安装前等待任务结束并退出旧版。

客户端优先通过局域网服务端读取检查结果；无法获取结果时尝试直接访问 GitHub。这里只中转版本信息，下载安装包仍访问 GitHub。仓库必须提供正式 Release 和匹配版本的 `fenpei_<版本>-1_amd64.deb`。私有仓库鉴权暂未接入。

默认更新仓库为 `zhu-hang131433/fenpei`。构建时可使用 `FENPEI_UPDATE_REPO=GitHub用户名/fenpei bash go-dist/build-release.sh` 覆盖默认仓库。运行时可通过同名环境变量覆盖。未配置仓库时明确显示提示，不会假报已是最新版。将版本常量改为新版本并推送对应 `v主版本.次版本.补丁版本` 标签后，GitHub Actions 会测试、构建并发布 Deb、便携包和 SHA-256 校验文件。

公开版本的上传平台凭据需在每台上传电脑单独配置，环境变量 `FENPEI_PLATFORM_PASSWORD` 和 `FENPEI_DAG_ACCESS_TOKEN` 优先；也可把 `go-dist/packaging/platform.example.json` 复制为 `${XDG_CONFIG_HOME:-$HOME/.config}/fenpei/platform.json`，填写真实值并限制文件权限为 `600`。配置不随公开安装包发布。已有工作目录的任务池、日志、接收文件及旧 Python 脚本均排除在 Git 仓库之外。
